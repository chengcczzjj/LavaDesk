# FlowWall 在线壁纸库接入设计

> 2026-09-27，按源码描述已实现的接入。站点：[FlowWall 发现页](https://www.flowwall.ai/wallpaper/discover)。开发容器的网络策略拦截了 `www.flowwall.ai`，站点真实的下载按钮、登录与付费限制尚未实测；接入按“捕获站点自己的下载”设计，不依赖页面结构或私有接口。

## 1. 目标

- 在软件里直接逛 FlowWall 的精选动态/4K 壁纸，不用切到浏览器再手动导入。
- 用户在页面上点下载后，文件自动检查、加入「我的壁纸」，并能一键设为壁纸。
- 下载来的壁纸与本地导入的壁纸用法一致（播放设置、多屏分配、组件命名空间、智能体按名字切换），同时保留来源信息。
- 不绕过站点的登录、会员或下载限制，不抓取私有接口，不替用户点下载。

## 2. 入口

| 入口 | 行为 |
| --- | --- |
| 主界面 → 壁纸资源 → **FlowWall 发现** | 打开内嵌页面（默认发现页）；应用运行期间保留浏览历史，登录状态跨重启保留 |
| 对话：“去 FlowWall 逛逛” | `wallpaper(action=flowwall)` 打开主界面的同一页面；智能体不代替用户下载 |
| `lingyue://` 链接（网页或其他程序发起） | 见 §6，打开页面或经用户确认后下载 |

## 3. 内嵌页面与隔离

- 页面在主窗口上层的 `WebContentsView` 中运行，位置跟随页面里的占位区域（ResizeObserver 同步）；切换到其他标签、打开应用自己的对话框或页面出错时移除视图，返回时恢复，历史与登录保留。
- 独立持久分区 `persist:flowwall`：登录只存在灵月里，与系统浏览器互不影响；`sandbox`、`contextIsolation`、无 preload、无 Node；权限只放行剪贴板写入与全屏，其余（摄像头、麦克风、定位、通知）一律拒绝。
- 导航分类（`src/shared/flowwall.ts`）：

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| internal | `flowwall.ai`、`flowwall.art` 及子域的 https 页面 | 留在内嵌页面（新窗口也在原视图打开） |
| auth | Google、Apple、Microsoft、GitHub、微信、QQ、微博登录页 | 允许弹出同分区的登录小窗，保留 `window.opener` 回传结果 |
| media | 链接直指 `.mp4/.webm/.mov/.mkv/.jpg/.png/.webp/.gif/.zip` | 转为下载 |
| external | 其他 https、http、mailto | 交给系统浏览器 |
| blocked | `file:`、`javascript:` 等 | 忽略 |

- 工具栏：后退/前进/刷新(停止)/回发现页、只读地址（锁图标 + 域名 + 路径）、“浏览器打开”、下载面板开关（进行中数量角标）。页面获得焦点时 `Alt+←/→`、`F5`/`Ctrl+R`、加载中 `Esc` 仍有效。

## 4. 下载逻辑

站点按钮触发的下载由分区的 `will-download` 统一接管，状态机：

```
downloading ──完成──> importing ──内容检查+导入──> completed
     │                                   └─失败──> failed（原因可读）
     ├─ 已在库里（同一来源）──────────────> duplicate（直接可设为壁纸）
     ├─ 用户取消 ───────────────────────> cancelled
     └─ 超过 2 GB / 网络中断 ────────────> failed
```

1. **识别**：按文件名、MIME、URL 扩展名判断是否为视频/图片/壁纸包；其他文件（文档、安装包）不接管，走系统默认保存。
2. **落盘**：写入 `userData/wallpaper-downloads/<下载 id>/`，大小超过 2 GB（与手动导入 ZIP 同一上限）立即取消。
3. **判重**：来源地址去掉查询串（CDN 签名每次不同）后，与历史中“已完成且壁纸仍在库里”的记录比较。判重与下载并行；小文件可能先下完，因此完成后要等判重答案再决定导入，已存在就不再复制第二份。
4. **按内容信任**：读取文件头签名（`src/shared/media-signature.ts`），必须与声明的类型一致；登录页、错误页伪装成 `.mp4` 会被拒绝。签名与扩展名不一致时按真实类型改名（如 PNG 被命名为 `.jpg`）。
5. **导入**：复用本地导入流程（`importWallpaperFile`），名称取详情页标题（去掉“| FlowWall AI”，列表页标题无意义时用文件名）；元数据写入 `Source=flowwall`、`SourceUrl`、`PageUrl`、`DownloadedAt`，作者记为 FlowWall。完成后删除临时目录。
6. **记录**：最近 60 条下载记录存入设置，重启后可见；“清空记录”不删除已导入的壁纸。

## 5. 下载后在软件里的使用

- 「我的壁纸」卡片显示 **FlowWall** 角标；详情侧栏“来源”显示 FlowWall 与下载日期，原页面地址保存在壁纸元数据（`PageUrl`）中。
- 下载面板里 **设为壁纸** 应用到当前选中的显示目标（与壁纸库工具栏一致），**在我的壁纸中查看** 跳到本地库；失败/取消的条目可 **回到下载页** 重试。
- 视频按视频壁纸播放（音量、速度、静音、多屏复制/延展分配都可用）；图片按静态壁纸；ZIP 包按网页壁纸包导入（沿用原有解压校验与按包独立来源）。
- 组件布局跟随壁纸：第一次切到下载的壁纸时，桌面组件是这张壁纸自己的（空）布局，与本地导入一致。
- 智能体把 FlowWall 壁纸列为来源“FlowWall”，可按名字切换、调节设置；离线时已下载的壁纸照常使用。
- 从库中删除后，下次下载同一文件会重新导入，而不是提示重复。

## 6. `lingyue://` 协议

- 路由：`lingyue://wallpaper/open?page=<FlowWall 页面>` 打开内嵌页面（非 FlowWall 页面回落到发现页）；`lingyue://wallpaper/import?url=<https 媒体地址>&title=<名称>&page=<来源页>` 请求下载。
- 导入请求一律弹窗确认并写明来源域名；非 FlowWall 域名以警告样式提示；只接受 https 与壁纸文件类型，下载后同样经过 §4 的内容检查。其他路由忽略。
- 仅安装版注册协议（`app.setAsDefaultProtocolClient`，`electron-builder.yml` 的 `protocols`）；已运行时由单实例 `second-instance` 转交，启动参数中的链接在初始化完成后处理。
- 该协议是为 FlowWall 页面将来提供“在灵月中打开/设为桌面壁纸”按钮预留的对接点，目前站点是否提供此类按钮未验证。

## 7. 验证

- `npm.cmd test`：`tests/flowwall.test.mjs` 覆盖导航分类、下载识别、文件签名、标题清理、判重键、协议解析；服务行为（确认后下载、内容拒绝、改名导入、判重竞态、取消确认不下载）与视图隔离/IPC 角色/协议注册契约。
- `npm.cmd run test:electron:smoke`：`flowwall` 组在真实 Electron 主进程中用本地替身站点验证分区隔离、无 Node/桥接、通知权限拒绝、`file:` 导航拦截、真实下载的改名导入、重复、伪装文件拒绝与临时目录清理。
- 开发构建可用 `LINGYUE_FLOWWALL_HOME=http://127.0.0.1:<端口>/...` 指向本地替身站点（打包版忽略）。
- 待验收：真实 FlowWall 站点的下载按钮形态（直链、`blob:`、需登录/会员）、登录弹窗流程、Windows 实机上的视图层级与缩放（非 100% DPI）、安装版协议注册。
