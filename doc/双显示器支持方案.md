# 灵月双显示器支持方案

## 调研结论

本次实现参考了 Windows 壁纸应用的通用做法：

- **Lively Wallpaper** 的公开命令文档把多屏布局分为 `per`、`span`、`duplicate`：每台屏幕独立壁纸、跨虚拟桌面延展、所有屏幕复制同一壁纸；同时用 monitor id 做单屏设置。
- **Wallpaper Engine** 的桌面壁纸模型同样把“显示目标”和“壁纸内容”分开，跨屏模式按显示器几何边界裁切渲染，而不是把两个屏幕当作一个普通 DOM 屏幕。
- Windows 的显示器坐标可能出现负数（副屏在主屏左侧或上方），不能假设屏幕从 `(0, 0)` 开始；显示器热插拔、缩放、分辨率变化后需要重新计算虚拟桌面矩形。

因此灵月采用“**所有模式都按显示器创建原生壁纸窗口**”方案：复制和按屏设置各自铺满；延展模式也不再创建一个跨越混合 DPI 的 BrowserWindow，而是让每个显示器窗口渲染同一份虚拟桌面构图，再用负的本地偏移只显示本屏切片。这样既保留连续延展效果，也避免负坐标、DPI 缩放和 WorkerW 子窗口坐标混用导致半张壁纸落到另一块屏幕。组件仍保留单画布，以避免每个组件创建原生窗口。

## 设置模式

| 模式 | 行为 |
| --- | --- |
| 仅主显示器 | 兼容原有单显示器行为，窗口只覆盖主显示器 |
| 复制到每台显示器 | 每台显示器独立铺满当前壁纸（视频各自播放） |
| 每台显示器单独设置 | 设置页选择不同壁纸；持久化使用 Win32 设备名稳定键，未指定时回退当前壁纸 |
| 跨屏延展 | 壁纸按虚拟桌面联合矩形以 `cover` 比例放大并铺满，显示器只显示自己的矩形区域 |

壁纸库顶部常驻显示布局选择器，可直接切换仅主屏、复制、按屏设置和跨屏延展。只有按屏设置模式会再显示目标显示器选择器；复制与跨屏延展模式应用新壁纸时保留当前布局，不会因为选过某台显示器而静默切回按屏设置。显示器设置页提供相同的模式状态、Windows 拓扑和逐屏壁纸分配入口，两处都写入同一份持久化配置。

组件是覆盖所有显示器的一层全局桌面布局，不会因为副屏单独换壁纸而整套替换。当前主显示器壁纸仍是组件配置命名空间；每个组件可以绑定主屏或副屏并保持自己的本地位置。这样避免两个壁纸配置中重复的组件 id 在单 Canvas 内冲突，也保证只更换副屏壁纸时组件不会跳动或消失。

## 边界与恢复

- Electron 提供逻辑坐标、工作区和缩放比例；Win32 `EnumDisplayMonitors` + `GetMonitorInfoW` 提供 `\\.\DISPLAYn` 设备名和物理像素矩形。二者按物理矩形匹配，壁纸分配和组件归属不再依赖可能变化的 Electron display id。
- `electron-as-wallpaper` 只负责 `SetParent`，不会处理多显示器布局。窗口贴入 WorkerW/Progman 后已是桌面子窗口，主进程必须把屏幕物理坐标经 `ScreenToClient` 转为父窗口本地坐标，再调用 `SetWindowPos`；每次贴合都用 `GetWindowRect` 校验最终物理矩形，失败不会再回退到 Electron 绝对坐标，并会自动重试。
- 组件永久保存为“稳定显示器键 + 显示器本地 x/y”。单一透明 Canvas 只在同步到 renderer 时将其映射为当前虚拟桌面坐标，拖拽结束后再反向映射；因此主屏、复制、按屏和延展之间切换不会改写组件的本地位置，跨屏拖拽才会改变归属。
- 旧版 Canvas 坐标只迁移一次：用旧 `widgetCoordinateOrigin` 还原绝对位置，再绑定到覆盖面积最大的显示器。断开的显示器组件暂时不渲染，重新连接同一设备后恢复原位。
- 窗口收到 `display-metrics-changed`、`display-added`、`display-removed` 后按当前模式增删原生壁纸窗口，并通知 renderer 与主界面拉取最新布局。
- 全屏遮挡判断改为“所有显示器都被覆盖”才暂停整套壁纸抽帧；副屏上的全屏应用不会误伤主屏组件。
- 毛玻璃不再只采样主壁纸窗口。每台壁纸窗口分别发送 `{ displayKey, bounds, data }`，Canvas 按组件绝对位置选择对应帧；web 壁纸或 renderer 断帧时，主进程也逐屏 `capturePage` 兜底。

## 验证与诊断

- 自动测试覆盖负坐标、不同分辨率、稳定键迁移、四种模式、延展切片、组件跨屏拖拽和 Electron id 变化。
- 开发机可验证 Win32 设备枚举、单主屏贴合、类型检查、lint、单元测试和生产构建；混合 DPI 双屏最终仍需在真实双屏设备上做验收，不能用单屏自动测试代替。
- 运行时拓扑、逻辑/物理边界、贴合方式、校验失败和重试会写入 `%APPDATA%\LavaDesk\logs\display-diagnostics.jsonl`，用于定位公司电脑特有的 Explorer、DPI 或显卡差异。
